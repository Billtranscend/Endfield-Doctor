# 设备识别方案（2026-11-07 讨论稿）

目标：巡检对每一台关键设备给出「它是什么、在哪、现在什么状态」三个确定的答案，错认率低到可以直接下结论。
现状的问题：巡检跟着状态标记走，正常运转的设备看不见；设备名靠标签首字猜，「气…」分不清气体散布机 / 气体反应炉 / 气体收集泵；
最远缩放下设备密集处 OCR 误读多；只认阻塞 / 空闲 / 关闭三种标记，散布机罢工图标不认。

## 一、俯瞰画面里能用的信号（720p，最远缩放，已核对截图）

| 信号 | 样子 | 可靠性 | 用途 |
|---|---|---|---|
| 标签图标 | 每个设备名左边一个白色图标，约 20×20 px，按设备类型固定（洪炉是炉子、封装机是两个胶囊、散布机是烧瓶+人、协议箱是柜子、暗管是弯头箭头…） | 高：图形固定、不受字体渲染影响、不随缩放变形（只变大小） | **设备类型的第一依据** |
| 标签首字 | 图标右边「天…」「封…」「气…」 | 中：首字 OCR 在密集处偶有错行；同首字多种设备 | 类型的第二依据，和图标交叉验证 |
| 状态标记 | 阻塞（红圈斜杠）、空闲（蓝 zz）、关闭（灰圈叉）、**罢工（橙圈感叹号+循环箭头，用户截图）** | 高（现有三种已校准）；罢工待做模板 | 状态 |
| 面板标题 | 点开后的全名 | 最高，但要点击、要等，慢 | 只在底账建立和存疑时用 |
| 设备模型外观 | 3D 模型 | 低：4 个朝向、被传送带和标签遮挡 | 不用 |

结论：**类型靠「图标 + 首字」双重匹配，位置靠已验证的坐标复用（跨次误差 1–3 px），状态靠标记。** 面板只在建底账时点一次。

## 二、分两层：建底账（一次）和巡检（每次）

### 第 1 层：设备底账（每张蓝图、每个分区做一次）

底账 = 分区里每台设备的 {类型, 坐标, 朝向无关, 所属链路}。按用户要求在**能看到设备全名的固定缩放档**下建，流程：

1. 进俯瞰 → 顶到地图左上角（现有 go_corner）→ 滚轮缩到约定的「底账缩放档」（滚几格要实验定，用小地图或协议核心大小校验到位）。
2. 按网格扫整个分区，每屏：OCR 全部标签（全名可见，词表只有 117 个建筑名，按词表纠错），记录每个标签的坐标和它左边图标的截图。
3. **不点面板**，除非标签 OCR 结果不在词表里或两次读不一致 → 点开读标题，顺便把这台的图标截图存成这类设备的模板。
4. 把该档坐标换算到最远缩放坐标系（比例在实验里标定：同一个标签在两档下的位置之比），和历史巡检里出现过的坐标对账：对得上的互相印证，对不上的标出来人工看。
5. 存 data/blueprints/<蓝图>/ledger/<分区>.json：[{name, x, y, icon_ok, confirmed_by: "ocr"|"panel"}]。

多次扫描并集只做补充（用户要求）：历史巡检见过、底账没有的坐标，列为「待确认」项，下次经过时点一次面板。

产出的附带收益：图标模板库 resource/icons/<设备名>.png，从底账扫描里自动裁出来，不用人工做。

### 第 2 层：定向巡检（每次，最远缩放，速度优先）

1. 排查树 ✗ → 给出要看的设备类型和分区。
2. 从底账取这些类型的全部坐标（例如 12 台天有洪炉、全部气体散布机），按屏分组，镜头逐屏过去。
3. 每屏：
   - **确认在看的是谁**：底账坐标附近 ±30 px 找标签，图标模板匹配 + 首字，两者都对才算确认；只对一个 → 记「存疑」，不下结论；
   - **读状态**：连拍 12 秒（盖住容量箱 10 秒周期），认四种标记；
   - 判定规则按类型：阻塞 / 空闲「每帧都在」才算持续；**罢工「出现过一次」就算问题**；关闭一帧就算。
4. 存疑的设备如果不超过 3 台，当场点开面板确认；超过 3 台说明镜头或底账有问题，报「本分区底账需重建」而不是硬下结论。

### 全量深度巡检（大改基地后）

保留现有两遍扫描，但两处改动：类型用图标 + 首字（不再只用首字），罢工标记加进去。扫完和底账对账：底账里有、这次一个标签都没看到的坐标，可能是设备被拆了 → 提示「底账过期，重建」。

## 三、要先做的实验（需要游戏，约 40 分钟）

| 实验 | 要定的参数 | 怎么做 |
|---|---|---|
| 底账缩放档 | 滚轮格数；该档的全名可见率 | 从最远缩放往里滚，每滚 2 格截一屏 OCR，取全名识别率 ≥ 95% 的最远一档 |
| 两档坐标换算 | 比例系数、原点偏移 | 同一屏里 5 个标签在两档下的坐标做线性拟合 |
| 该档镜头速度 | PAN_SPEED | 按住方向键 0.6 秒，标签位移 |
| 图标模板 | 每类设备 1 张，最远缩放 | 从现有 debug/shots 里直接裁，已有 8 个分区的截图；散布机缺（没单独认出过），底账扫描时补 |
| 罢工图标 | 模板、颜色阈值 | 用户把一个惰气准入口限速调低制造罢工 → 截图 → 恢复；同时核对不被阻塞的红色筛选误认（罢工是橙色） |
| 「设备列表」(Z) | 游戏自带的俯瞰设备列表长什么样 | 右侧菜单有「Z 设备列表」，如果它列出本分区全部设备且能跳转，底账可以直接从它抄，比扫描准 |

最后一项值得先试：如果游戏自带的设备列表能用，第 1 层的扫描大部分可以省掉。

## 四、精度目标和验收

- 类型：底账里每台设备的类型以面板标题为准抽查 20 台，错 0 台才算过。
- 位置：定向巡检按底账坐标过去，±30 px 内找到对应标签的比例 ≥ 95%。
- 状态：用户注入故障（关一台、限速一个准入口）→ 定向巡检抓到；正常基地连跑 3 次 → 0 问题。
- 回归：tests/faults 的 17 个用例继续通过（底账为空时回退到现在的首字猜测，行为不变）。

## 五、已记录待查的问题（改动时一并检查）

- 散布机间歇罢工的周期，12 秒窗口是否够。
- 罢工图标是否也出现在洪炉「无环境」、断电等情况。
- 耐压罐爆仓 → 塑形机堵 → 惰气消耗变少的链条。
- expert.py 里「惰气理论消耗 < 基准 → 断气」要降级为提示，判断交给巡检看散布机。
