## 已完成并实测

- **状态标记**（`src/badges.py`，模板 `resource/badges/`）：红圆环斜杠 = 阻塞，蓝色 zz = 空闲中。带遮罩的平方差匹配，一屏内全部找到、无误报。
- **标记会闪烁**：满负荷产线里设备会短暂出现标记。点之前再截一张图核对，消失了就记为「（闪烁）」跳过；点开后面板是「生产中」的也当闪烁。
- **点开设备**（`src/patrol.py`）：先点标记上方的设备标签（OCR），再试固定偏移，再在周围转一圈；点到物流件就关掉换位置。面板标题按「包含的最长建筑名」匹配（`data/building_names.json`）。
- **面板守护**：用右上角关闭按钮的模板判断面板是否开着；点击前、点击后、关闭后都查，关不上会重试三次。这是之前扫描中途卡死（管道面板留着没关、WASD 推不动镜头）的根因。
- **配方识别**（`src/panel_recipe.py`）：配方栏整行居中（行宽 = 46×格数 + 71，中心 675.5），原料格在左、产物格在右，中间 79 像素的箭头块；需要气体环境的配方上方多一行标签、整排下移 10 像素，所以纵坐标取实际检出的格子。图标按固定尺寸（24–36）在格子中心比对、只允许 4 像素微调；灌装瓶/耐压罐（空容器 + 液滴叠画）不计分，配方由其余格子决定；原料/产物按排列组合取总差异最小的分配。验证过：灌装机（芽针/锦草）、配件机、塑形机、精炼炉（双产物）、天有洪炉（稳定环境）。
- **地区**：从面板左侧「武陵仓库」读出，写进巡检 JSON 的 `region`。
- **全基地扫描**（`--sweep`）：先退到左上角，再蛇形覆盖。武陵城 4 行 × 3–4 列，55 个标记、18 个闪烁、37 台设备，约 8 分钟。
- **联合结论**（`src/combine.py`，Opus 子代理写）：阻塞 → 产物爆仓 / 下游回堵 / 下游在等备路原料 → 正常，否则问题；空闲 → 备路未触发 / 原料为 0 往上游追 / 原料有库存却没到；配方没认出时按设备候选产物兜底；废水处理机空闲算正常。武陵城全基地结果：**问题 0**，待确认 9（7 台没点开、1 台惰气灌装机是备路、1 台反应池面板布局不同）。
- **缺矿缺气液**（`src/sources.py`）：对照蓝图档案的参考简报，按地区报「缺设备」或「来源供不上」。
- **蓝图档案**（`src/blueprint.py`，`data/blueprints/<名>/`）：tier_rules.json + reference_brief.json；diagnose/combine/sources 都按 `--blueprint` 读。

## 多故障测试 B–F 对账（2026-11-04 15:00–15:30）

用户同时做了五处；三分区全流程 0 问题后，按简报连锁和巡检线索补了这些规则（combine.py / sources.py）：
- 源头设备（水泵、气体收集泵、矿机）阻塞 = 它后面的暗管/传送带断了；同流体的根因存在时挂到根因下作「可能的断点」。
- 流体有余（产 ≥ 耗 × 1.2）但 ≥ 2 台消费者空闲 = 准入口限速/管道。
- 固体原料库存充足、该固体满产、消耗 < 理论 × 0.6、消费者空闲 = 送不到，**准入口物品改错放建议首位**（F：应龙关赤铜块准入口被改成砂叶）。
- 产耗同时比蓝图参考低一半以上且生产设备阻塞 = 可能输出传送带断（B：分离芯封装机，爆仓掩盖，只能到「待确认」）。
- 连锁归根：sources 判定的源头流体（清水）把所有受它影响的待确认收成一条「根因」。
- 源头物品 产 < 耗、库存在降 = 矿机没开满/被关/地区等级纯度（E：矿机在协议区域外，巡检看不到，只能靠简报）。
- 上游阻塞 + 下游空闲 = 中间断了，同一条线的几对合并（蓝铁粉末线，理论消耗从蓝图 30 掉到 0）。
- **理论消耗比蓝图参考下降 = 有消费者被断开**（C：武陵城惰气准入口 6→0，惰气理论消耗 150→144，正好少一个 6 的口；蓝铁粉末 30→0 同理）。这是最便宜、最通用的「断开」信号：传送带断、准入口限速 0、取货口物品改错都会让理论消耗掉。
结果：C、D、E、F 报为问题；B 为待确认（爆仓掩盖）。武陵城蓝铁粉末那条线不在用户的五处里，应是基地原有问题，待用户确认。

## 2026-11-04 晚：瞬时标记去噪（做法）
